# AI 系統開發實戰學院｜UI 設計規格 v1.6

狀態：已確認，作為下一步 TRD（技術施工圖）的視覺依據。
適用範圍：首頁與後續教學頁的共用視覺、插圖、卡片與響應式規則。
產品邊界：頁面佈局與互動必須遵守已確認 PRD 與互動原型；不得為了「不單調」自行增加版型、功能或互動。

## 1. 設計主題

主題名稱：**AI 系統開發實戰學院｜清楚、可驗收、帶有工程感的學習路徑**。

- 感受：專業、清楚、有陪伴感；不用過度科技感或裝飾壓過學習內容。
- 資訊優先順序：先看標題與下一步，再看說明，最後才是插圖與裝飾。
- 角色系統：隼鳥為 AI 教學引導者，Eddy 為人類學習者與實作回饋；只作為情境引導，不取代文字說明。
- 每個區塊最多一組 Eddy＋隼鳥與 3–5 個小互動點。

| 深藍輔助色 | `--blue-deep` | `#123f78` | 深色按鈕文字、次層級標題 |
| 輔助強調色 | `--teal` | `#2c9e98` | 分段、次要操作與狀態 |

## 3. 吉祥物與插圖

### 3.1 隼鳥吉祥物 v2

- 物種與細節：隼猛禽、白色臉頰、深色羽毛、海軍藍／電藍／青綠服裝系統、黃橘喙與爪。
- 服裝：深藍連帽上衣、耳機、黑色束口褲、深色慢跑鞋；雙臂為一般衣袖，不露出翅膀；雙手為深藍黑色皮革五指手套。
- 情境：基準／靈感、快樂、憤怒、苦惱、哀求、專注；表情以眉眼與鳥喙區分，符號只補強情緒。
- 素材：網站只使用 `assets/mascot/falcon-v2/transparent/` 的透明 PNG。

### 3.2 Eddy 人類學習者

- 頭部：捲起的濃黑髮、粗黑眉、透明飛行眼鏡、暖膚色與清楚友善表情。
- 服裝：紅色立領機能外套、黑色內搭與長褲、黑色慢跑鞋；左手黑色智慧手錶固定青綠螢幕。
- 手勢：只取已定義的攤掌、指向、比讚、OK、數三、停止、托掌、自然放鬆，並用於提問、思考、確認或實作回饋；每一手五指完整、比例自然。
- 素材狀態：三視圖與手勢庫是繪製規格，不可直接當透明情境素材；需要新場景時必須從此規格建立相符角色圖。

### 3.3 角色構圖

- 隼鳥優先採左側／上側講解位置，Eddy 採右側／下側學習位置；可依閱讀方向微調，但不得造成主次顛倒。
- 同一畫面不新增第三位角色、不使用肢體接觸；Eddy 的紅色與隼鳥藍綠系保持可辨識分離。
- 小符號不可遮住任何角色的眼睛、嘴喙、眼鏡、手錶或手勢。

### 3.4 小圖示與流程插圖

- 使用透明 PNG，風格與吉祥物一致的 3D 插圖。
- 系統類型卡、學習入口卡與發布卡的插圖固定在**右上角**。
- 一般卡片文字由左下往右上建立斜對角閱讀動線；流程圖節點可在圖片內承載「編號＋階段名稱」，但完整規則必須同步存在 HTML 文字版。
- 圖示尺寸隨卡片容器寬度縮放；必須保留標題與內文安全區。
- 每張圖片皆需提供有意義的 `alt`；純裝飾吉祥物使用空白 `alt` 並由周邊文字提供語意。

### 3.5 亮色雙角色流程圖

- 背景使用 `--paper`、`--sky` 或接近白色的淺藍；不得使用深藍／黑色滿版背景。
- 00–10 節點為白底圓角卡，編號使用電藍徽章；名稱使用深藍粗體。青綠線與箭頭連接三列路徑，金黃只用於靈感燈泡等小重點。
- 隼鳥位於左側教學位，以指向或攤掌連接第一個節點；Eddy 位於右側學習位，觀看平板／筆記。兩位角色不得遮住節點名稱或箭頭。
- 節點文字至少須在桌面一眼可辨；手機採全圖等比縮放，文字小於可讀範圍時由下方 HTML 文字版承接，不以裁切或橫向捲動處理。

### 3.6 詳細教學與案例區

- 詳細教學區直接置於每階段主流程，使用清楚的步驟卡與可讀段落；不得呈現來源逐行轉錄或行號說明。
- 個人工作台案例以淺藍白底三欄預覽呈現「今天、專案、本階段產物」；手機改為單欄，不裁切文字。
- 詳細教學、個人工作台案例與提示詞必須用不同 eyebrow／標籤標明用途，避免誤認案例是固定產品規則。
- 01–09 的提示詞區以等寬文字保留來源原文與換行；提示詞之外的教學敘述使用自然的第一人稱主動語態。
- 教學文案以「當下卡點 → 我採取的動作 → 我留下的產物」帶領閱讀；避免連續、機械地重複「我會」或套用規格書式句型。

## 4. 版面與元件規範

### 4.1 頁面骨架

1. 固定導覽：學習地圖、實際案例、文件模板、手機 App、提示詞、AI 協作、模型指南、名詞、作品分享；案例與模板保持為獨立資源頁。
2. Hero：頁面目的、核心說明、必要 CTA，以及單一情境吉祥物。
3. 主內容：依 PRD／原型定義的順序呈現，不能因視覺效果調換操作與資訊順序。
4. 頁尾：資料安全、名詞、模型指南、來源與維護連結。

### 4.1.1 學習地圖

- 桌面使用中央路徑線與左右交錯關卡卡片；節點顯示階段編號與第幾關。
- 每張卡片固定包含區域、關卡名稱、說明、過關產物與操作按鈕。
- 已完成關卡使用青綠狀態；未完成關卡使用藍色，不能只靠顏色表達。
- 手機改為左側路徑線與右側單欄卡片，不產生橫向捲動。

### 4.2 資訊卡

- 白底、圓角、細邊框、柔和陰影；不使用厚重漸層或高對比背景搶走內容。
- 卡片高度依實際文字與圖片內容收合；不可為視覺整齊強制留下大片空白。
- 同一組卡片可由最長內容決定該列高度，但內容本身不得被裁切。
- 系統類型卡必須有「可套用」標籤、標題、專屬介紹與相關插圖。
- 不可使用通用重複文案取代各卡片說明。

### 4.3 按鈕與連結

- 主要動作：藍底白字；次要動作：白底深藍字；輔助動作：青綠底白字。
- 按鈕最小高度 46px，手機維持可點擊尺寸。
- 外部連結以 `↗` 或清楚文案表達，避免讓使用者誤以為是站內頁。
- 卡片連結、Hero CTA、手機選單的目的地以原型規格為準；未定義的項目不新增行為。

## 5. 響應式規則

| 寬度 | 欄位與行為 |
| --- | --- |
| 桌面（> 940px） | 系統與平台卡三欄；Hero 左文右卡；完整導覽。 |
| 平板（641–940px） | 一般資訊卡雙欄；保留右上圖示與文字安全區。 |
| 手機（≤ 640px） | 所有卡片單欄；主導覽收合為選單；Hero 與流程卡由多欄改單欄。 |

- 不允許橫向捲動。
- 文字不可因縮放而低於可閱讀大小。
- 右上圖示、吉祥物與互動點在窄螢幕不可遮住標題、內文、按鈕或臉部。

## 7. 驗收清單

- [ ] 所有頁面都只呈現 PRD 與原型已定義的內容、順序與互動。
- [ ] 吉祥物、插圖、流程圖與小圖示維持同一套色彩與角色細節。
- [ ] Eddy 的髮型、飛行眼鏡、紅色外套、左手手錶與黑色慢跑鞋符合角色母版；隼鳥 v2 的手套、衣袖、鞋與表情符合角色規格。
- [ ] 圖示不遮住文字或吉祥物臉部，且有透明背景與適當替代文字。
- [ ] 卡片使用專屬介紹文字並依內容收合，沒有無意義大面積空白。
- [ ] 桌面、平板、手機的欄位與閱讀順序符合本規格。
- [ ] 所有 CTA、卡片連結、手機選單與外部連結依原型指定目的地運作。
- [ ] 流程圖維持亮色背景，00–10 名稱完整且不遮住；隼鳥與 Eddy 的教學／學習關係清楚。

## 8. 交給 TRD 的輸入

TRD 需要將本文件轉成：

1. 共用 CSS token、斷點、卡片與插圖元件的實作責任。
2. 路由／連結對照表與點擊後的預期頁面狀態。
3. 圖片資產路徑、替代文字、透明背景與載入失敗處理。
4. 桌面、平板、手機的視覺測試案例與無橫向捲動檢查。
5. 不得新增未在 PRD／原型確認的版型與互動的變更控制規則。
6. 以 [網頁插圖資產總表](illustration-asset-catalog.md) 作為所有圖片路徑、使用狀態與角色關係的唯一清單。

### 首頁案例入口與五個主題頁（2026-09-06）

六張系統類型卡沿用原有插圖與三欄／響應式卡片樣式，整張改為原生連結，加入可見鍵盤焦點與「查看完整案例」。五個案例頁沿用個人工作台的標題、圖解、目標卡、階段卡與複製面板；各自配置 SVG 說明圖和分支流程圖，圖可放大且附文字版。Android／iOS 均為習慣追蹤 App，各寫平台特定重點。新主題不顯示既有工作台 Demo 的可操作宣稱。

### 主題流程圖視覺修正（2026-09-06）

五個新案例依使用者提供的淺藍參考圖改用白色立體卡片、青色流程線、隼鳥與 Eddy 雙角色圖。依管理、教學、資料整理、Android 與 iOS 習慣追蹤更換角色動作、道具與六步主題流程。每頁用一張主題流程圖取代前一版兩張深色 SVG；附一致的六步文字版，點擊可看原圖。個人工作台沿用原圖。00–10 課程提示詞與角色流程圖的 01–06 使用步驟分開呈現。


### 2026-09-06 新增兩個案例入口
實際案例總覽擴充為八個主題，新增會員管理系統及既有專案檢查與接續開發，各有獨立頁面與 00–10 階段單一可複製提示詞。會員案例限定管理者名單、編輯、狀態與搜尋，不含付款或會員登入。既有專案先唯讀盤點證據與缺口，再回到最早缺少的前置階段；保留既有成果與可回復版本，逐階段補齊、檢查、接續。共用課程完整要求與 Skill 指令。新入口沿用現有卡片與文字流程，尚非已交付的產品。


### 2026-09-06 案例起點與圖像流程更新
七個一般案例只顯示 01–10，只有既有專案檢查與接續開發保留 00 現況盤點。學習地圖原有 00 不變。會員管理與既有專案新增淺藍底、隼鳥與 Eddy 的圖像流程，八個案例均提供主題流程圖片。
