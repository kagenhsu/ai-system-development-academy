# AI 系統開發實戰學院｜UI 設計規格 v1.1

狀態：已確認，作為下一步 TRD（技術施工圖）的視覺依據。
適用範圍：首頁與後續教學頁的共用視覺、插圖、卡片與響應式規則。
產品邊界：頁面佈局與互動必須遵守已確認 PRD 與互動原型；不得為了「不單調」自行增加版型、功能或互動。

## 1. 設計主題

主題名稱：**AI 系統開發實戰學院｜清楚、可驗收、帶有工程感的學習路徑**。

- 感受：專業、清楚、有陪伴感；不用過度科技感或裝飾壓過學習內容。
- 資訊優先順序：先看標題與下一步，再看說明，最後才是插圖與裝飾。
- 吉祥物角色：隼猛禽擬人角色；只作為主角色與情境引導，不取代文字說明。
- 每個區塊最多一位 Hero 吉祥物與 3–5 個小互動點。

## 2. 配色系統

| 類型 | Token | 色碼 | 使用位置 |
| --- | --- | --- | --- |
| 主要結構色 | `--ink` | `#102943` | 標題、深色文字、頁尾、結構重點 |
| 主要互動色 | `--blue` | `#2467b2` | 主要按鈕、流程、重點連結 |
| 深藍輔助色 | `--blue-deep` | `#123f78` | 深色按鈕文字、次層級標題 |
| 輔助強調色 | `--teal` | `#2c9e98` | 分段、次要操作與狀態 |
| 提示色 | `--yellow` | `#f7c84b` | 靈感、提醒與少量互動點 |
| 淺藍底色 | `--sky` | `#eaf4fb` | 流程卡、次要區塊底色 |
| 淺綠底色 | `--mint` | `#dff5ef` | 階段區分、補充狀態 |

## 3. 吉祥物與插圖

### 3.1 吉祥物

- 物種與細節：隼猛禽、白色臉頰、深色羽毛、海軍藍／電藍／青綠服裝系統、黃橘喙與爪。
- 服裝：休閒帽 T、休閒褲、耳機；後續動作必須沿用相同身高比例、服裝與羽毛細節。
- 情境：靈感、程式、驗證、慶祝、感謝；動作與本區內容有直接關聯。
- 禁止：小圖示不可遮住吉祥物臉部；不可在同一區堆疊多個主角色。

### 3.2 小圖示與流程插圖

- 使用透明 PNG，風格與吉祥物一致的 3D 插圖。
- 系統類型卡、學習入口卡與發布卡的插圖固定在**右上角**。
- 文字由左下往右上建立斜對角閱讀動線；圖片僅支援辨識，不承載必要文字。
- 圖示尺寸隨卡片容器寬度縮放；必須保留標題與內文安全區。
- 每張圖片皆需提供有意義的 `alt`；純裝飾吉祥物使用空白 `alt` 並由周邊文字提供語意。

## 4. 版面與元件規範

### 4.1 頁面骨架

1. 固定導覽：學習路線、十階段、加入主畫面、手機 App、提示詞、模型指南、名詞、作品分享。
2. Hero：頁面目的、核心說明、必要 CTA，以及單一情境吉祥物。
3. 主內容：依 PRD／原型定義的順序呈現，不能因視覺效果調換操作與資訊順序。
4. 頁尾：資料安全、名詞、模型指南、來源與維護連結。

### 4.2 資訊卡

- 白底、圓角、細邊框、柔和陰影；不使用厚重漸層或高對比背景搶走內容。
- 卡片高度依實際文字與圖片內容收合；不可為視覺整齊強制留下大片空白。
- 同一組卡片可由最長內容決定該列高度，但內容本身不得被裁切。
- 系統類型卡必須有「可套用」標籤、標題、專屬介紹與相關插圖。
- 不可使用通用重複文案取代各卡片說明。

### 4.3 按鈕與連結

- 主要動作：藍底白字；次要動作：白底深藍字；輔助動作：青綠底白字。
- 按鈕最小高度 46px，手機維持可點擊尺寸。
- 外部連結以 `↗` 或清楚文案表達，避免讓使用者誤以為是站內頁。
- 卡片連結、Hero CTA、手機選單的目的地以原型規格為準；未定義的項目不新增行為。

## 5. 響應式規則

| 寬度 | 欄位與行為 |
| --- | --- |
| 桌面（> 940px） | 系統與平台卡三欄；Hero 左文右卡；完整導覽。 |
| 平板（641–940px） | 一般資訊卡雙欄；保留右上圖示與文字安全區。 |
| 手機（≤ 640px） | 所有卡片單欄；主導覽收合為選單；Hero 與流程卡由多欄改單欄。 |

- 不允許橫向捲動。
- 文字不可因縮放而低於可閱讀大小。
- 右上圖示、吉祥物與互動點在窄螢幕不可遮住標題、內文、按鈕或臉部。

## 6. 已確認的首頁需求對照

| 區塊 | 產品需求 | UI／原型落點 |
| --- | --- | --- |
| Hero | 說明從想法到 Web、Android、iOS 的路徑 | 左側文案與 CTA；右側四步流程卡與靈感吉祥物。 |
| 來源與致謝 | 呈現來源、邊界與感謝 | 感謝姿勢吉祥物位於文字左側；小互動點不遮臉。 |
| 六張系統卡 | 提供可套用的系統方向 | 專屬說明、右上透明圖示、內容自適應高度。 |
| 開發流程圖 | 讓讀者先看懂三段式路徑 | 有階段名稱、箭頭方向與文字版。 |
| 學習入口 | 進入名詞與模型指南 | 右上圖示、清楚 CTA、內文優先。 |
| 手機發布 | 比較加入主畫面、Android、iOS 路線 | 三張平台卡、對應圖示與各自目的地。 |

## 7. 驗收清單

- [ ] 所有頁面都只呈現 PRD 與原型已定義的內容、順序與互動。
- [ ] 吉祥物、插圖、流程圖與小圖示維持同一套色彩與角色細節。
- [ ] 圖示不遮住文字或吉祥物臉部，且有透明背景與適當替代文字。
- [ ] 卡片使用專屬介紹文字並依內容收合，沒有無意義大面積空白。
- [ ] 桌面、平板、手機的欄位與閱讀順序符合本規格。
- [ ] 所有 CTA、卡片連結、手機選單與外部連結依原型指定目的地運作。
