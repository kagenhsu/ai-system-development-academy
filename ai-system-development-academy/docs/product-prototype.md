# 產品原型規格 v2.4｜第四步：頁面交互

依據：[PRD v2.3](product-requirements.md)。

本文件只定義讀者如何在網站中前進、查看、下載與記錄進度。角色、插圖、色彩、版面與響應式細節，依 [UI 設計規格](ui-design-spec.md) 執行。

## 1. 原型要回答的問題

讀者第一次進站時，是否能回答四件事？

1. 我現在要從哪一步開始？
2. 這一步要準備什麼、完成後會留下什麼？
3. 我卡住時可以去哪裡查？
4. Web 驗收後，我下一步可以怎麼使用或延伸？

## 2. 全站主要路徑

```text
首頁
  → 階段 00 或學習地圖
  → 階段 00–10：輸入 → 教學 → 產物 → 驗收 → 下一階段
  → Web 驗收後：繼續 Web／加入主畫面／Android／iOS
```

| 入口 | 使用者操作 | 預期結果 | 狀態 |
| --- | --- | --- | --- |
| 首頁「從我的第一步開始」 | 點擊 CTA | 前往 `stage-00.html`。 | 已定義 |
| 首頁「先看學習地圖」 | 點擊 CTA | 前往 `roadmap.html`。 | 已定義 |
| 學習地圖任一關 | 點擊「進入關卡」 | 前往對應 `stage-xx.html`；已完成時顯示「再次查看」。 | 已定義 |
| 階段頁的下一步 | 點擊下一階段 CTA | 前往下一個階段；10 完成後前往手機使用選擇。 | 已定義 |
| 主導覽 | 點擊「學習地圖」「實際案例」或其他站內連結 | 前往各自獨立的資源頁。 | 已定義 |
| 手機選單 | 開啟後點擊關閉、遮罩或 Esc | 關閉選單，焦點回到開啟按鈕。 | 已定義 |

## 3. 十一階段頁面交互

### 3.1 每頁固定閱讀順序

1. 目前階段與要解決的情境。
2. 本階段輸入與本階段產物。
3. 第一人稱詳細教學與操作流程，包含具體輸入、結果、檢查與錯誤修正示範。
4. 個人工作台本階段完整產物、版本、合格／不合格對照與相關名詞。
5. 本課 Skill 搭配、平台啟動示例、預期行為與失敗處理，再接原提示詞或操作原則；兩者分區標示，不覆蓋原文。
6. 下一課材料交接與專屬驗收；案例與模板由頁首獨立入口進入。
7. 上一階段／下一階段導覽。

### 3.2 提示詞交互

Skill 教學依 [搭配表](skill-teaching-map.md)：00 展示取得→啟動→驗證，05 展示依任務選設計 Skill；以可選取文字與已驗證來源連結呈現。此輪不新增網站安裝／執行按鈕或自動平台判斷，平台用明確標題分開。缺來源、依賴或未測時顯示對應狀態；FAQ 提供失敗與無 Skill 替代流程。

子 Agent 教學依 [分工表](subagent-teaching-map.md)：00 與模型指南加入單 Agent／子 Agent 選路；各課以可複製任務卡呈現角色、目標、範圍、材料、禁止事項、證據與回傳格式；進度示意分開顯示已啟動、執行中、需要處理、已完成及主 Agent已整合。網站只展示教學，不直接啟動 Agent。

| 狀態 | 使用者操作 | 預期結果 |
| --- | --- | --- |
| 01–09 提示詞載入完成 | 點擊「複製本階段提示詞」 | 複製來源原文；成功或失敗皆提供可理解提示。 |
| 原教程來源檔無法載入 | 開啟階段頁 | 顯示「原教程提示詞載入失敗」；不以改寫內容代替原文。 |
| 00、10 | 開啟提示詞區 | 顯示操作原則，不顯示假造的可複製提示詞。 |

### 3.3 模板與產物交互

| 元件 | 使用者操作 | 預期結果 |
| --- | --- | --- |
| 階段 04 工作台 Demo | 切換總覽、今日工作、專案、每日回顧；切換工作狀態、新增示範工作、暫存回顧 | 畫面立即顯示對應狀態與回饋；重新整理後還原，不宣稱資料持久化或正式系統完成。 |
| 舊模板網址 | 開啟 `templates.html` | 轉向學習地圖；桌面與手機導覽不再提供此入口。 |
| 頁首「實際案例」 | 點擊導覽 | 前往 `case.html`，依 00–10 查看具體動作、目前狀態與可複製的實作提示詞。 |
| 各課完成範例（待實作） | 查看本階段完整成果 | 在本課提供可閱讀的完整產物與版本；不以 `case.html` 概念介紹代替。尚未備妥時顯示【待補】，不提供誤導性的完整範例按鈕。 |
| 修正與交接說明（待實作） | 閱讀輸入、結果與修正對照 | 同頁文字展示錯誤、判斷理由、修正後結果及回修階段；列出保存檔名、位置、版本及下一課使用方式，不自動操作學員檔案。 |
| 階段 09 開發驗收教學 | 點擊「下載階段驗收紀錄模板」 | 直接下載紀錄產物、實測、證據、待確認與交接結論的空白文件。 |

### 3.4 階段進度交互

| 狀態 | 使用者操作 | 預期結果 |
| --- | --- | --- |
| 驗收清單未全勾選 | 點擊「標記本階段完成」 | 阻擋完成，提示先完成四項檢查。 |
| 驗收清單全勾選 | 點擊「標記本階段完成」 | 只在目前瀏覽器記錄該階段完成；不保存文件，不宣稱已驗收系統。 |
| 進度頁 | 點擊「清除匿名進度」並確認 | 清除目前瀏覽器內的進度並重新整理頁面。 |

**【需產品確認】** 勾選完成後是否應自動導向下一階段，或維持讓讀者自行閱讀與選擇；目前原型維持原頁，不自動跳轉。

## 4. 學習支援與手機延伸

| 情境 | 使用者操作 | 預期結果 |
| --- | --- | --- |
| 看不懂名詞 | 點擊名詞入口或階段名詞標籤 | 前往名詞頁，再回到相關階段。 |
| 不知道 AI 工具與模型差異 | 點擊模型指南 | 查看工具、模型、權限與官方來源；不由網站替讀者自動選模型。 |
| 做到一半卡住 | 開啟 FAQ | 看到對應問題的具體回查步驟。 |
| Web 已驗收 | 點擊手機延伸入口 | 比較繼續 Web、加入主畫面、Android、iOS。 |
| 選擇加入主畫面 | 點擊安裝或手動安裝說明 | 依瀏覽器能力顯示安裝提示或操作步驟。 |
| 選擇 Android／iOS | 點擊對應路線 | 查看發布準備步驟與外部官方來源。 |

**【需產品確認】** 是否要在 Web 驗收完成後才解除手機路線 CTA，或讓所有讀者都可提早閱讀；目前所有路線皆可先閱讀，避免把教學資訊鎖住。

## 6. 非交互規則

- 隼鳥與 Eddy 是閱讀情境引導，不可變成對話、輪播、彈窗或未定義操作。
- 系統類型卡是方向參考，不點擊就直接啟動任何開發流程。
- 流程圖提供文字等價內容；圖片不可成為唯一資訊來源。
- 外部 TikTok 與平台官方文件在新分頁開啟，並清楚標示外部來源。

## 7. 原型驗收清單

- [ ] 首頁、路線與每個階段都能讓讀者找到下一步。
- [ ] 每個階段都有輸入、操作、產物、專屬驗收與下一階段入口。
- [ ] 01–09 提示詞可複製來源原文；00、10 不補造提示詞。
- [ ] 模板能下載，且不保存讀者文件。
- [ ] 階段 09 清楚區分「自我驗收」與「開發驗收紀錄」，並可下載階段驗收紀錄模板。
- [ ] 進度、清除進度與完成標記的範圍說明正確。
- [ ] 名詞、模型、FAQ 與手機路線能作為卡住時的回查入口。
- [ ] 所有【需產品確認】項目未被實作成新功能或對外承諾。

### 六案例逐階段 Skill 啟用（2026-09-06）

六個案例每階段的可複製內容加入相關 Skill 啟用、用途與範圍。01–09 仍完整載入學習地圖原提示詞；00、10 新增明確標示的案例 Skill 操作補充，不宣稱原教程提供提示詞。後續操作提示詞也帶入本階段 Skill。網站僅提供指令，不執行 Skill；接收指令的 AI 需核對可用性、讀取規則並回報缺少情況。

- 00：請使用 $find-skills 核對本案例後續所需 Skill 是否可用，只盤點工具能力與專案工作空間；缺少 Skill 時回報，不自動安裝或開始開發。
- 01：請使用 $grill-me 進行一問一答需求訪談，每次只問一題，依下方課程要求整理本案例需求。
- 02：請使用 $doc-coauthoring 整理已確認需求，依下方課程要求拆成模組、功能、子功能與優先級；只完成完整功能清單，不提前寫 PRD 或程式。
- 03：請使用 $doc-coauthoring 撰寫本案例 PRD，完整遵守下方課程章節與逐功能要求，檢查缺漏、前後一致性及可驗收性。
- 04：請使用 $prototype 驗證本案例已確認 PRD 的頁面與操作流程。這次沿用既定課程結構，只做一套可操作原型，不產生多套視覺方向；不以拋棄式原型冒充正式產品。
- 05：請使用 $ui-ux-pro-max 設計本案例的 UI，嚴格依已確認 PRD、原型與參考風格，核對元件狀態、資訊層級與響應式，不新增產品功能。
- 06：請使用 $doc-coauthoring 整理本案例 TRD，逐項轉化已確認 PRD，保留下方十章與全部子項，檢查資料流、接口、約束及文件一致性；不擅自新增功能或決定未確認技術選型。
- 07：請使用 $writing-plans 將本案例已確認 PRD 與 TRD 拆成有前置依賴、交付物及驗收方法的開發計畫；本階段只規劃，不開始執行。
- 08：請使用 $executing-plans 按本案例已確認計畫開發，使用 $test-driven-development 驗證需要測試的功能與資料行為。遇到錯誤或測試失敗時使用 $systematic-debugging 先查原因；所有修改遵守下方課程要求與已確認範圍。
- 09：請使用 $verification-before-completion 依本案例 PRD 驗收並留下實測證據，再使用 $web-design-guidelines 檢查 Web 介面。UI 檢查不代替功能、資料保存或 Android／iOS 實機測試；版本管理仍完整依照下方課程規則。
- 10：請使用 $verification-before-completion 核對本案例交付版本與發布前證據，依課程操作原則整理啟動、備份及回復方式；先確認目的地與公開內容，再執行已獲同意的上傳或發布。
