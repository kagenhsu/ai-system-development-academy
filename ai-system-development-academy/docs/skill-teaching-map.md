# Skill 取得、啟動與各課搭配教學 v1.0

日期：2026-09-05
狀態：已核對本機說明與官方啟動文件；教學補強規格／搭配提案。未安裝、未修改 Skill、未進行各平台端到端實測。

## 1. 補進網站的入口

子 Agent 並不是 Skill；如何搭配、分工與驗證見 [子 Agent 教學表](subagent-teaching-map.md)。00 與模型指南需把主 Agent、子 Agent、Skill、MCP／外部工具及 AGENTS.md 一起說清楚。

- 00 開發準備：先學 Skill、提示詞、插件、MCP 的差別；再做一次找出、取得、啟動及驗證。
- 每課：新增「這課使用哪個 Skill」說明，列必需／選用、任務、材料、啟動文字、預期行為、產物與失敗處理；沒有合適 Skill 可用原提示詞完成，不強制每課安裝。
- 模型指南：Agent／模型／Skill／外部工具分工，以及選用條件。
- 提示詞頁：把「啟動 Skill 的教學示例」與「原教程提示詞」分開，原文不得為了加入 Skill 名稱而覆蓋改寫。
- FAQ：找不到、名稱重複、未觸發、缺依賴、工具不支援、執行超出指定範圍的處理。
- agent-skill 名詞頁：加入啟動與驗證例；不只解釋定義。
- 不先新增獨立 skill.html 路由；若內容過長，另行確認資訊架構，避免舊規格中的未實作入口被誤稱已存在。

## 2. 新手必學的取得與啟動流程

1. 先辨識目前使用 Codex、Claude Code 或其他工具，確認版本與工作目錄。
2. 在目前工具的可用清單找完整名稱；有同名項目時核對來源、用途及版本，不重複安裝或直接覆蓋。
3. 未安裝時，教材需提供可核對的原作者／官方來源、取得方式、適用版本與依賴。先讀 SKILL.md 與引用檔，不執行未知來源的整包安裝指令。
4. 依工具支援方式安裝或匯入整個 Skill 資料夾／插件，不能只貼 SKILL.md 而漏掉 references、scripts 等檔案。安裝前記錄修改位置與同名衝突；本教材此輪未確定的公開下載網址標【待確認】，不提供假下載。
5. 回到可用清單確認可被發現，再明確選取名稱與提供本課材料。若仍未出現，依該工具版本檢查路徑、格式、載入範圍及重新載入方式，不一律要求重裝。
6. 先做不改正式專案的小測試：要求讀取 Skill、說明本次採用的流程、缺少的材料與預期產物。
7. 以實際載入紀錄與符合該 Skill 的行為確認使用；AI 口頭說「已啟動」不是充分證據。接著完成一次小任務，再檢查產物品質。

### 平台啟動對照

| 工具 | 教材示例 | 限制與驗證 |
| --- | --- | --- |
| Codex | 明確提及 `$grill-me`，或從目前介面可用 Skill 選取後補上任務 | 官方文件支持 `$<skill-name>`；CLI／IDE 可用 `/skills` 或輸入 `$` 找 Skill。桌面版實際選單位置需以錄製時版本擷取，不套用 Claude 的指令。 |
| Claude Code | `/grill-me` 後接任務 | 只在已安裝且允許使用者呼叫時使用；插件可能有命名空間，照清單完整名稱選取，不保證短名稱通用。 |
| 其他 AI 工具 | 先查是否支援 Agent Skills 及其取得／啟動方式 | 不保證相容；不支援時可手動貼教學提示詞，但需標明這是提示詞替代流程，並非 Skill 已啟動。 |

可複製的補充示例（不是原教程提示詞；尚未在學員環境實測）：

```text
$grill-me
我的題目是個人工作台。請先讀取這個 Skill，確認本次工作目錄與需求資料。
請每次只問一個會影響需求的問題；目前只做需求訪談，不寫程式。
資訊足夠後整理需求文件草稿，缺少的規則標記待確認。
```

Claude Code 的對應示例把第一行改成已核對清單中的 `/grill-me`；其他材料與任務要求相同。不能在任何聊天框輸入斜線就宣稱工具會載入技能。

官方依據（2026-09-05 查閱，非本機操作驗收）：[Codex Skills](https://learn.chatgpt.com/docs/build-skills)、[Codex App Server 的 Skill 輸入](https://learn.chatgpt.com/zh-Hant/docs/app-server)、[Claude Code Skills](https://code.claude.com/docs/en/skills)。

## 3. 00–10 各課搭配與啟動任務

以下名稱依目前可讀的 Skill 定義整理；「適合用途」不等於學員已安裝或本站已完成整合。Codex 示例如下，其他平台按上一節換成當地可用名稱。

| 課程 | Skill 搭配 | 啟動時交什麼／怎麼說 | 預期產物與檢查 |
| --- | --- | --- | --- |
| 00 | `ai-personal-workbench-tutorial` 作整體引導；安裝工具為按需選用 | 請使用教學 Skill，只檢查平台、工作空間、必要工具與缺少材料，先不開發 | 準備清單與一次載入／小任務驗證；不把安裝等同完成 |
| 01 | `grill-me` | `$grill-me`＋初步想法；限定需求訪談、一次一題 | 有追問脈絡的需求草稿與待確認事項 |
| 02 | 原階段提示詞；需求不清時再用 `grill-me` | 提供已確認需求，先拆能力與優先級；缺少規則再追問 | 完整功能清單；不因 Skill 自增 UI 或功能 |
| 03 | 原 PRD 提示詞；`to-prd` 僅作進階選用 | 先確認任務是否只寫本機文件。此版 `to-prd` 有發布到 issue tracker 的用途，不作新手預設 | 與已確認功能對應的完整 PRD；未授權不得對外發布 |
| 04 | 原原型提示詞；`prototype` 只在要釐清一個特定流程時選用 | 給 PRD，明說要驗證哪條流程、不要多版視覺探索；確認原型只是拋棄式實驗 | 可操作流程及發現的決策；不可把該 Skill 的「省測試」規則套到正式開發 |
| 05 | 工作台優先評估 `ui-ux-pro-max`；`frontend-design` 可作實作選項；首頁／品牌頁才按需用 `design-taste-frontend` | 一次選一個主要設計 Skill，交 PRD、原型、現有設計規則、目標頁與允許修改範圍 | 可審閱的 UI 與對照說明，不能加入未确认功能；候選依賴需驗證後才教成可用 |
| 05／08 參考圖還原 | `image-to-code` 僅在有參考圖且依賴齊全時選用 | 給設計圖、已確認原型、保留項目與目標頁；先查引用檔是否齊全 | 對照畫面與版型／樣式實作；目前本機版本不列為新手可直接用的必需項 |
| 06 | 原 TRD 提示詞；說明資料流可選 `baoyu-diagram` | 先給已確認技術關係與節點文案，明確沿用學院亮色規則，不使用預設深色風格 | TRD 與可編輯說明圖；圖不能代替技術決策或測試 |
| 07 | 原開發計畫提示詞／教學 Skill | 提供已確認 PRD、TRD，只拆本輪任務與依賴，不進行實作 | 任務、產物、驗收與交接；不強加另一個計畫 Skill |
| 08 | 教學 Skill 引導；必要時接續 05 的前端 Skill | 明確限定已批准的一段功能、程式目錄、資料與驗收；正式工作台才評估既有建造 Skill | 程式、可操作結果與測試；不重建另一套正式資料來源 |
| 09 | `web-design-guidelines` 作 UI 稽核選用 | 指定實際檔案／頁面，先查最新規則，只列問題、位置與影響，不立即改檔 | UI 問題清單；另做功能、資料與瀏覽器實測，不能以 UI 稽核代替全部驗收 |
| 10 | 教學 Skill／原操作原則；不預設部署 Skill | 提供驗收結果與選定使用方式，先列備份、發布及回復檢查 | 使用與發布計畫；對外發布是獨立動作，不因啟動 Skill 自動授權 |

## 4. 設計 Skill 的選路與交接

沒有參考圖的工作台 → 先確認 PRD／原型 → 選一個適合表單、表格與流程的設計 Skill → UI 確認 → 實作 → `web-design-guidelines` 稽核 → 操作與資料驗收。

已有參考圖 → 核對可使用的圖與已確認原型 → 檢查 `image-to-code` 依賴 → 還原 → 實際截圖比較 → UI 稽核與操作驗收。缺依賴時回到已驗證的原型／前端流程，不補造同名工具。

首頁／品牌頁 → 可選 `design-taste-frontend`，先說明頁面、受眾與視覺方向；既有品牌、色彩、角色與已確認流程優先，不照預設風格大改工作台。

製作流程圖 → 可選 `baoyu-diagram`，先給內容正確的節點和關係，再指定亮色、中文字與文字等價內容；生成的圖不是操作證據。

教學用的 UI 啟動示例（補充文字，非已實測指令）：

```text
請使用 ui-ux-pro-max，依照我提供的 PRD、互動原型與既有設計規則，
只整理「今日工作」頁的 UI 建議。先讀取 Skill 並檢查必要依賴。
列出資訊層級、表單／清單狀態及桌面／手機差異，不自行新增功能。
目前先交付可審閱的建議，不直接修改正式網站。
```

## 6. 圖文與驗收增補

- D-SK01：Skill、提示詞、Agent、模型、MCP／插件分工圖，放在 00 與模型指南；須有 HTML 文字。
- D-SK02：按頁面／任務選設計 Skill 的分支圖，放在 05；呈現工作台、品牌頁、參考圖還原與稽核的不同用途。
- S-SK01：在各工具查找、取得／安裝、選取及第一次使用的實際畫面組，記錄版本；Codex 與 Claude Code 分開擷取。
- S-SK02：正確載入與產物、找不到／依賴不足的實際例子；不能用 AI 自述或生成截圖充當使用成功證據。
- 每課卡片最低欄位：名稱與來源、用途、必需／選用、平台版本、輸入材料、啟動示例、預期行為、成果、未生效排查、無 Skill 替代流程。
- 驗收需分開記錄：來源可核對 → 安裝／可發現 → 實際載入 → 任務跑通 → 產物驗收。全部欄位完成才能標為該平台已驗證教學。
- 不一次啟動一串設計 Skill；前一份產物經確認才交下一個 Skill。原始提示詞保留來源，新增啟動文字另標本站補充。
