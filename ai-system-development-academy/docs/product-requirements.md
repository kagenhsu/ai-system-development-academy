# 產品需求文件 PRD v1.1

## 1. 背景與目的

AI 系統開發實戰學院提供第一次做系統的讀者一條可逐步驗收的學習路徑。首頁的目的不是展示炫技效果，而是讓讀者在短時間內理解：要先說清楚需求、再建立規格、完成並驗收 Web，最後才延伸 Android／iOS。

## 2. 目標使用者

- 第一次使用 AI 協助開發系統的人。
- 想把工作台、管理系統、教學網站或資料工具做成可用 Web 的個人使用者。
- 需要理解功能清單、PRD、原型、UI、TRD 與驗收關係的學習者。

## 3. 範圍

### 包含

- 靜態教學網站與十階段內容導覽。
- 首頁 Hero、來源與致謝、系統類型、流程圖、學習入口與手機發布卡。
- 站內頁面連結、外部來源連結、手機選單與本機匿名進度。

### 不包含

- 使用者帳號、付款、課程解鎖、個人資料蒐集、雲端資料庫、後端 API。
- 自動替使用者開發系統、對外發布或做商業承諾。

## 4. 功能需求

### FR-01｜首頁閱讀與導覽

讀者開啟首頁時，系統必須以 Hero 清楚呈現學習目的、兩個 CTA 與四步流程卡。主導覽在桌面可見，手機改為可開關選單。

**驗收條件：** CTA 與導覽連到既定站內頁；手機選單可由開啟、關閉與 Esc 回到原頁。

### FR-02｜系統類型卡

首頁必須提供六張系統類型卡。每張卡含「可套用」標籤、標題、與標題相符的專屬介紹，以及相關透明插圖。

**驗收條件：** 不使用重複通用介紹；圖示固定右上角；文字不被遮住；卡高依內容收合。

### FR-03｜學習流程與入口

首頁必須有含文字與箭頭方向的三段式流程圖，以及可前往名詞庫與模型指南的入口卡。

**驗收條件：** 流程圖具文字版；入口卡 CTA 指向正確頁面；圖片載入失敗不影響主要文字與連結。

### FR-04｜手機發布路線

首頁必須區分加入主畫面、Android／Google Play、iPhone／App Store 三種路線。

**驗收條件：** 三張卡各自提供正確說明與目的地；不把加入主畫面宣稱為商店上架。

### FR-05｜來源與致謝

首頁必須呈現來源、整理與驗證聲明，以及外部原始影片連結。

**驗收條件：** 清楚表達內容不是原影片逐字重製；外部來源以外部連結提示呈現。

## 5. 內容與視覺規則

- 內容順序遵守原型規格；不可因美化而調換 CTA、流程或路徑順序。
- 每個區塊最多一位主吉祥物，周邊 3–5 個小互動點。
- 右上角插圖不得遮住文字或吉祥物臉部。
- 所有重要資訊由 HTML 文字呈現，不只存在圖片裡。

## 6. 非功能需求

| 類別 | 要求 |
| --- | --- |
| 響應式 | 桌面三欄、平板雙欄、手機單欄；不得有橫向捲動。 |
| 可近用性 | 圖片有適當 alt；按鈕可鍵盤操作；文字與背景具有清楚對比。 |
| 效能 | 圖片使用適當尺寸；非必要裝飾不可阻礙主要內容載入。 |
| 內容安全 | 不公開密碼、金鑰、私人資料、完整影片字幕或未授權內容。 |

## 7. 異常情境

| 情境 | 預期處理 |
| --- | --- |
| 圖片無法載入 | 顯示 alt；文字、CTA 與卡片功能仍可使用。 |
| 窄螢幕 | 卡片改單欄，圖示縮放並保留文字安全區。 |
| 外部連結失效 | 本站不改寫或備份來源內容；連結仍明確標為外部來源。 |
| 使用者按 Esc | 開啟中的手機選單關閉，焦點回到開啟按鈕。 |
