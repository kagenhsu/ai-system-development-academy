# 產品需求文件 PRD v2.4

## 1. 產品初衷

AI 系統開發實戰學院要幫助第一次使用 AI 開發系統的人，把「我有一個想法」走成「我有一個能使用、能檢查、能持續修改的 Web 系統」。

本站不承諾 AI 會自動做完產品，也不把讀者當成只會照貼提示詞的人。它要帶讀者逐步釐清問題、留下文件、檢查結果，最後決定是否把已驗收的 Web 延伸到手機。

個人工作台是全站的示範案例；學習者可替換成管理系統、教學網站、資料整理工具或自己的題目。

## 2. 目標使用者與成功結果

| 對象 | 他正在面對的問題 | 完成後能做到什麼 |
| --- | --- | --- |
| 第一次用 AI 做系統的人 | 不知道從哪一步開始，容易直接跳進寫程式或畫 UI | 能依十一階段完成自己的第一套 Web 開發文件與驗收流程。 |
| 有模糊想法的個人使用者 | 想法散亂，不知道第一版該做什麼 | 能把真實使用情境整理成需求、功能清單與 P0 範圍。 |
| 想持續改善系統的人 | 做完後無法判斷是否完成，也無法安全修改 | 能保留測試、版本與回復依據，再決定是否發布或延伸手機使用。 |

## 3. 產品範圍與邊界

### 包含

- 十一個階段（00–10）的教學、輸入、產物、驗收與下一步。
- 以個人工作台貫穿的案例、空白 Markdown 模板與名詞說明。
- 原教程提示詞、外部來源與手機延伸路線。
- 本機瀏覽器內的匿名階段進度。

### 不包含

- 帳號、付款、課程解鎖、雲端資料庫、後端 API 或個人文件上傳。
- 替學員自動開發、代替驗收、代替發布，或做任何商業承諾。
- 把本機能開啟的網站宣稱為已正式上線。

## 4. 核心學習體驗

### FR-01｜從首頁找到自己的第一步

讀者開啟首頁後，要能理解本站是從「釐清需求」開始，而不是立刻寫程式；並能前往階段 00 或學習地圖。

**驗收條件：** 首頁有清楚的產品目的、第一關 CTA、學習地圖入口，以及 Web 完成後才延伸手機的說明。

### 學習地圖

- 將 00–10 呈現為依序推進的十一關，分為釐清、施工圖、開發交付三個區域。
- 每關必須顯示學習目標、過關產物、入口與匿名完成狀態。
- Web 完成點之後，才顯示加入主畫面、Android、iOS 三條手機支線。
- 地圖視覺不可取代關卡順序、標題與文字；手機版必須回到單一路徑閱讀。

### FR-02｜十一階段可接續完成

每一個 `stage-00.html` 至 `stage-10.html` 必須提供：目前要解決的情境、本階段輸入、操作方法、可檢查產物、專屬驗收與下一階段入口。

**階段閉環：** 上一階段的產物是下一階段的輸入；資料不完整或規則衝突時，讀者應回到受影響的前一階段確認，而不是跳過。

| 階段群組 | 讀者完成後留下的核心成果 |
| --- | --- |
| 00–03 | 工作空間、需求、功能清單、PRD |
| 04–07 | 互動原型、UI 規格、TRD、開發計畫 |
| 08–10 | 可操作 Web、測試與版本紀錄、使用／發布計畫 |

### FR-03｜來源教材與提示詞使用規則

`0 基础做 App 保姆级教程.txt` 是本站的教材基準，原樣保存於 `assets/source/0-basic-app-tutorial-source.txt`。

- 教學方法、操作資訊與案例：重新編排成自然、有溫度的第一人稱教學，不逐行轉錄來源。
- 01–09 的可複製提示詞：直接保留來源原文與換行，不得改寫。
- 00、10 沒有來源獨立提示詞：只呈現操作原則，不補造提示詞。
- 提示詞前說明要準備的輸入；提示詞後提醒讀者檢查與保存產物。

### FR-04｜文件模板與驗收不代替使用者判斷

移除文件模板獨立頁與桌面、手機導覽入口；舊網址轉向學習地圖。階段 09 保留階段驗收紀錄 Markdown 空白模板直接下載。

「實際案例」是跨階段資源，從頁首主導覽進入獨立頁面，不在每一個階段頁重複放置混合資源區塊。

階段勾選只用來記錄閱讀進度；不得被描述為平台已驗收、已保存，或證明讀者的系統已完成。讀者要以「產物連結、實測步驟、結果、證據位置、待確認、交接結論」建立開發驗收紀錄。

**驗收條件：** 模板可下載；下載內容沒有真實資料；頁面清楚說明文件應保存到讀者自己的專案資料夾。

### FR-05｜必要的學習支援與下一條路

網站需提供名詞、工具／模型指南、常見問題、案例與安全提醒，幫讀者在卡住時回到正確階段處理。

Web 通過驗收後，讀者可選擇：繼續以 Web 使用、加入手機主畫面，或再進入 Android／iOS 的發布準備；三者需明確區分。

### FR-06｜完整教學需要操作、成果、修正與交接

2026-09-05 確認教學補強方向；以下為待實作要求，非已完成成果。對應功能清單 v1.6 及 [T01–T06 修正清單](teaching-gap-review.md)。

- 極簡版保留快速路線；本專案沿用 00–10，以個人工作台完成同一題目的開發教學。
- 每課必須展示具體輸入／操作、AI 或工具結果、檢查依據、至少一次錯誤與修正後結果，讓新手知道如何做和如何判斷。
- 完整案例產物須對應本課與版本，並能作為下一課輸入；00、08、10 可使用準備、操作與發布紀錄，不強行提供不存在的文件或提示詞。
- 每課交代檔名、保存位置、確認版本、下一課要交給 AI 的材料及示例說法；網站不接收、保存或自動交接學員文件。
- 每課提供合格／不合格對照及回修階段；既有勾選仍只記錄本機進度。
- 既有走讀文件中屬於學院網站的內容只作參考，不冒充個人工作台成果；案例業務規則缺漏標記【需產品確認】，不自行新增功能。
- 範例尚未完成時顯示【待補】，不將概念頁標為完整文件；教學模擬與已實測案例需明確區分，後者附證據。

**驗收條件：** 逐課可找到操作、完整成果、錯誤修正、合格對照與下一課交接。對正確服務目錄及版本，實測導覽、範例入口、提示詞複製、模板下載、進度保存與桌面／手機閱讀，未測維持【待確認】。

### FR-07｜Skill 的取得、啟動與任務搭配（待實作）

依 [Skill 教學與各課搭配表](skill-teaching-map.md)，00 提供平台識別、來源／版本、取得、同名衝突、啟動與小任務驗證；每課說明必需／選用、輸入、啟動文字、預期行為、成果與未生效排查。無適合或可用 Skill 時可使用原提示詞，不強制安裝。

05 必須分開說明工作台 UI、品牌頁、參考圖還原與成品稽核，不以名稱相近推定用途相同。名稱、來源及依賴需核對；平台啟動方式不可混用。安裝、可發現、載入、任務跑通與產物驗收分開標記。

啟動示例屬本站補充，不能覆蓋原提示詞。不在網站自動安裝、執行 Skill、處理金鑰或發布成果。工具版本／依賴未實測保持【待確認】，網站與教學 Skill 流程差異先列待同步。

**驗收：** 新手能依 00 完成一次載入與小任務；各課找到對應搭配與失敗替代路徑；05 能按頁面與目標選用；證據需包含平台、版本、來源、操作及產物，不能只引用 AI 自述。

### FR-08｜子 Agent 分工、整合與驗證（待實作）

依 [子 Agent 教學表](subagent-teaching-map.md)，說明主 Agent、子 Agent、Skill、MCP 與 AGENTS.md 的分工；提供直接委派示例、適用／不適用判斷、任務交付格式、00–10 搭配及自訂 Agent 進階入口。

需求訪談維持單一主線；平行工作優先使用探索、測試、分流及審查。需要寫檔時必須分清檔案責任，避免同檔衝突。子 Agent繼承當前工具與權限限制，不取得額外外部操作授權。主 Agent須等待、整合、處理衝突並重新驗證重要結論。

**驗收：** 學員能判斷何時使用單 Agent或子 Agent，寫出含目標、範圍、證據與回傳格式的任務，完成一個唯讀平行案例，並分清「Agent已啟動、個別任務完成、結果已整合、最終已驗證」四種狀態。

## 5. 內容語氣與信任原則

- 用「當下卡點 → 我採取的動作 → 我留下的產物」帶領閱讀。
- 用第一人稱主動語態，但避免機械重複「我會」或像 AI 指令／規格書的語氣。
- 技術、平台政策與安全限制必須清楚精準，不為口語化而省略條件。
- 不把插圖、角色、流程圖或勾選當成唯一資訊來源；必要規則必須以 HTML 文字呈現。
- 不公開密碼、金鑰、個資、公司資料、完整影片字幕或未授權內容。

## 6. 非功能需求

| 類別 | 要求 |
| --- | --- |
| 響應式 | 桌面、平板、手機皆可閱讀；不得因教學內容出現橫向捲動。 |
| 可近用性 | 圖片有合適替代文字；按鈕可鍵盤操作；文字與背景清楚可辨。 |
| 隱私 | 學習進度只保存於目前瀏覽器；不保存文件、截圖、作品或身份資料。 |
| 來源 | 外部來源以外部連結呈現；正式發布與平台政策以當下官方文件為準。 |

## 7. 驗收範圍

- 每個階段均能清楚找到輸入、操作、產物、驗收與下一步。
- 01–09 提示詞逐字對應來源原文；其他教學文字不假裝是原文。
- 個人工作台案例能讓讀者理解同一個題目如何跨階段推進。
- 模板、名詞、FAQ、手機路線與來源連結不承諾未實作功能。
- 視覺角色、插圖、版面與手勢規則，依 [UI 設計規格](ui-design-spec.md) 驗收；互動行為依 [產品原型規格](product-prototype.md) 驗收。
