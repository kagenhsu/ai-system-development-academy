# 教學與範例驗收清單

## Skill 驗收

- [ ] 模糊需求會先逐題詢問，而不是直接產生大型專案。
- [ ] 每次只問一個仍會改變結果的問題。
- [ ] 會明確區分草稿、待確認與正式資料。
- [ ] 需求變更會要求同步檢查相關文件。
- [ ] 會先完成 Web，再談桌面封裝。
- [ ] Windows 與 macOS 指令、路徑和啟動方式沒有混用。
- [ ] 不會把第三方案例或影片內容當成使用者的產品需求。

## 範例 Web 驗收

- [ ] 可只輸入工作名稱建立收件匣工作。
- [ ] 首頁會顯示新工作。
- [ ] 可切換工作狀態。
- [ ] 可追加進度，且舊紀錄仍存在。
- [ ] 重新整理後資料仍存在。
- [ ] 空資料、載入中與錯誤狀態可理解。
- [ ] AI 草稿未確認前不會寫入正式資料。

## 證據分級

| 證據 | 能證明什麼 | 不能證明什麼 |
| --- | --- | --- |
| `node --check` | JavaScript 語法可解析 | 功能可用 |
| 單元／API 測試 | 測試情境通過 | 真實畫面已驗收 |
| 本機服務啟動 | 服務可啟動 | 所有路由、資料與登入正常 |
| 瀏覽器操作 | 指定流程可操作 | 已部署到正式環境 |
| 部署後網址檢查 | 指定環境可訪問 | 未測的功能與資料安全 |

## 不可宣稱

- 零成本、零設定或 AI 全自動完成。
- 只看首頁就代表整個系統完成。
- 只有示範資料就代表正式資料流程完成。
- 只有自動測試就代表 Windows／macOS 桌面版完成。
