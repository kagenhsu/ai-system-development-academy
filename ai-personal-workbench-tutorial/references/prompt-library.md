# 提示詞庫

以下提示詞是教學模板，不是授權 AI 自行決定產品規則。每次貼入前，先把使用者自己的情境補入空白處。

## 1. 需求訪談

```text
請使用一問一答方式，協助我規劃 AI 個人工作台。
每次只問一個問題，等我回答後再問下一題。
請依序釐清：使用者、每天反覆處理的工作、真實痛點、使用時機、資料來源、
需要的功能、不需要的功能、主要設備、資料保存、AI 可做與不可做的事、驗收方式。
我回答模糊時，請只追問最關鍵的一點。
資訊足夠後，先輸出「需求草稿」與「仍待確認」，不要直接寫程式。

我想做的工具：AI 個人工作台
我的初步想法：把每天的工作、專案、進度、提醒與回顧集中管理。
現在開始第一個問題。
```

## 2. 功能清單

```text
請根據已確認的需求，產生完整功能清單。
使用「模組 → 功能 → 子功能」三層結構，並標記 P0 必做、P1 後續、P2 未來。
每項只寫能力、解決的使用者問題與驗收條件，不寫 UI 美化細節。
不得自行新增未確認的業務規則；缺少資訊請列在「待確認」。
輸出完整版本，不只輸出變更片段。
```

## 3. PRD、原型與 TRD

```text
請依目前已確認的功能清單產生 PRD。
每項功能說明輸入、操作、輸出、規則、限制、正常情境、空資料與錯誤情境。
不確定的地方標示【待產品確認】，不要用常見產品邏輯代替我的決定。
```

```text
請依 PRD 產生互動原型規格，列出頁面、彈窗、表單、按鈕、預設狀態與點擊結果。
只描述資訊架構與互動，不描述配色或視覺風格。
所有與 PRD 不一致或資料不足之處列為【待產品確認】。
```

```text
請把已確認的 PRD 轉成 TRD。
逐項列出前端、後端、資料模型、API、輸入驗證、錯誤處理、權限、日誌、測試與風險。
忠實轉換，不自行指定框架、資料庫或第三方服務；方案選擇列為待確認。
```

## 4. 開發與驗收

```text
請先交叉檢查需求、功能清單、PRD、原型與 TRD。
只列出衝突、缺失與待確認，不要開始編碼。
確認後，本輪只實作一個垂直切片：新增工作 → 首頁顯示 → 保存 → 重新整理後仍存在。
請先列出要修改的檔案與驗收條件，再開始。
不要同時加入登入、AI、提醒、外部通知或桌面封裝。
```

```text
請只做驗收，不要修改程式。
分開回報自動測試、API、資料持久化、指定頁面、桌面版面與手機寬度檢查。
分類為：已通過、失敗、待確認、下一步。
沒有實際操作或畫面證據的項目，不得標示為已驗收。
```

## 5. 跨平台與桌面延伸

```text
Web 版本已完成驗收。請提出 Windows 與 macOS 桌面封裝方案比較。
保留同一套核心資料、權限與業務規則；不要先修改 Web 核心。
列出每個方案的安裝方式、檔案存放、更新、備份、失敗回復與驗收步驟。
先提出方案與風險，不要直接封裝或發布。
```
