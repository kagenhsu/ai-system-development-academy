# AI 個人工作台教學

本 Skill 教使用者建立自己的 AI 個人工作台，不把任何第三方影片、案例或產品當成固定答案。以工作型單人、本機優先的工作台作為教學範例，先完成 Web，再評估 Windows／macOS 桌面封裝。

## 核心邊界

- 先問痛點、使用者、每天反覆處理的對象、流程與最後要看到的結果；每次只問一個仍會改變設計的問題。
- 使用者確認需求前只產生草稿與選項，不修改正式程式、正式 Markdown／Obsidian 資料、部署設定或外部服務。
- 將「AI 個人工作台」理解為由 AI 協助設計、每天可記錄生活或工作的系統；長期使用後，才找出值得加入 AI 整理、規劃、分析與提醒的自動化工作，升級成「AI 個人駕駛艙」。
- 駕駛艙中的使用者就是主管或老闆，負責確認決定與下達指示；AI 只能先提出草稿、摘要與建議，不能未經確認執行外部動作。
- 以繁體中文、白話和可照做的步驟回覆；技術名詞後補一句用途說明。
- 不承諾零成本、零環境或 AI 自動完成；清楚區分草稿、已實作、已測試、已驗收與已發布。
- 第一版不把手機 App 當成必要範圍。Web 完成驗收後，才規劃 Windows／macOS 桌面封裝；手機另列後續階段。

## 工作流程

依序帶領使用者完成：

```text
痛點 → 需求訪談 → 功能清單 → PRD → 互動原型 → UI
→ TRD → 開發計畫 → Web 垂直切片 → 測試驗收 → 桌面延伸
```

每一階段輸出：目的、輸入、產物、待確認事項、驗收條件與下一階段入口。需求變更後，要求重新檢查受影響的功能清單、PRD、原型、TRD 與測試條件，不只修改單一段落。

## 使用模式

### 新手從零開始

先讀 `references/workbench-case.md` 和 `assets/project-brief-template.md`，再用 `references/prompt-library.md` 中對應階段的提示詞。先完成最小垂直切片：「新增一項工作 → 顯示在首頁 → 重新整理後仍存在」。

### 延續既有工作台

先唯讀檢查 README、規格、啟動入口、前端、API、資料儲存、測試與 Git 狀態。若是既有 `personal-workbench-cockpit` 或實際 AI 個人工作台，保留其資料真相與未提交修改，不從範例重新建立第二套資料來源。

### 與既有建造 Skill 串接

本 Skill 完成需求確認、教學產物與最小 Web 垂直切片後，若使用者要建立、改版或持續使用真實工作台，改用已安裝的 `personal-workbench-cockpit`。讀 `references/existing-skill-integration.md` 取得分工與串接規則，不覆蓋既有 Skill 的資料安全、人工確認與驗收規則。

### Windows／macOS 環境

需要環境指令時讀 `references/windows-macos.md`。先確認 Node.js、專案路徑、啟動方式與服務埠；不要把 Windows 路徑或 PowerShell 指令直接套到 macOS。

### 驗收與發布

先讀 `references/acceptance.md`。自動測試、指定路由、資料持久化、實際畫面與部署結果分開回報。沒有做瀏覽器或指定裝置檢查時，標記「視覺驗收待確認」。GitHub、公開網站、外部通知、正式 Vault 寫入與桌面發布都需要使用者明確確認。

## 範例產品邊界

教學範例可以包含今日工作、收件匣、任務狀態、專案、追加進度、提醒、每日回顧與 AI 摘要草稿。AI 預設只讀取去識別化摘要並產生草稿；使用者確認後才寫入正式資料。不要把公司機密、個資、密碼、Token、API Key 或真實 Vault 路徑放入 Skill、網站或範例資料。

## 回報格式

每完成一階段，回報：

1. 完成了什麼。
2. 如何確認。
3. 哪些仍待確認。
4. 下一個最小步驟。

不要把「可以啟動」寫成「功能已完成」，不要把推測寫成事實。
